# 转写稿 → 纪要：抽取规则

口语转写稿和纪要之间隔着一层判断。这一层做错，后面排版再漂亮，交付物也只是一份"排版整齐的流水账"。

## 1. 四段模型

任何会议纪要都可以归到这四段，缺哪段就写"本次会议未涉及"，不要编：

1. **总结**——本次会议在判断什么、达成了什么共识、还卡在哪。读者只看这一页也应该能转述给别人。
2. **讨论记录**——按议题展开，每个议题下是各方说了什么、依据是什么、分歧在哪。
3. **行动项**——谁、做什么、什么时候之前完成。责任方要具体到角色。
4. **后续讨论与交流**——还没定的事、风险提示、以及纪要本身的处理口径（脱敏、时效、传阅范围）。

四段对应 PDF 的四页结构（见 `miaoji-layout.md` 第 6 节）。

## 2. 读稿顺序

不要从第一行读到最后一行。转写稿通常 40 分钟以上、几百上千行，按下面三遍走：

**第一遍·扫信号**（只读标题和关键词，不读细节）：
找议题切换词（"下一个""还有一个""我们再看看""最后一个问题"）、
转场词（"其实""说白了""关键是""我觉得这里有个问题"）、
结论词（"所以""总的来说""这就意味着""共识是"）、
数据词（数字、百分比、金额、时间点）。
这些词标出了议题边界和会议真正在意的地方。

**第二遍·抽骨架**：按第一遍的边界把稿子切成议题块，每块只记三件事——
讨论的**问题**是什么、给出的**依据**是什么、形成的**判断**是什么。

**第三遍·补细节**：只回头读跟骨架里"判断"直接相关的段落。
跟判断无关的闲聊、寒暄、设备故障、重复表述，全部丢掉。

## 3. 什么该进，什么不该进

| 进 | 不进 |
|---|---|
| 改变判断的事实、数据、案例 | 寒暄与流程性对话 |
| 各方立场与分歧 | 同一句话的重复表达 |
| 达成的共识与明确的待办 | 说话时的犹豫、口头禅 |
| 影响行动项的约束条件 | 未经核实的传闻（除非明确标注为待核） |
| 被明确指出的风险 | 对在场人外貌、性格的评价性描述 |

一个判断标准：**删掉它，读者对会议的结论会不会变？** 会变就留，不会变就删。
按这个标准，"我觉得这个挺有意思的"永远不进。

## 4. 发言人一律角色化

纪要面向可能外传的场景，发言人用**角色 + 立场**，不写真名：

- ✅ `社区运营方提出：现在最不缺技术，能把项目往前推的人很少。`
- ❌ `张某某认为现在技术太多了。`

角色取自转写稿里可确定的关系，不自己发明头衔：

- `OPC 社区运营负责人`、`校方教师代表`、`在读研三学生`
- `双方共同`（行动项里指需要校方与运营方协同完成的事项）

角色化之后，句子要补上"谁在什么位置上说的"，
否则读者看到"社区运营方提出"也不知道这是他的主张还是会议的结论。
两者用句式区分：主张用"提出/认为/表示"，会议结论用"会议形成的判断是/会议认可/共同认可"。

## 5. 隐私与数据标注

### 5.1 不落纸的内容

以下类别默认不记录，除非用户明确要求保留：

- 导师姓名、用人单位名称、学位论文选题
- 个人身份信息、联系方式、求职意向、薪酬明细
- 对具体个人的评价性描述与外貌描写

替代写法：写成角色（"校方教师代表"）、写成范畴（"某校内创业载体"）、
或者直接省略该细节但保留其**影响**（例如"入驻条件未向研究生公开推送"）。

**交付前必做一次检索**：把转写稿里出现过的真实姓名、单位名、选题关键词列成一张禁写清单，
对写好的 HTML 源跑一次检索，确认 0 命中。
清单来自转写稿本身（发言人的自称、同伴的姓名、单位简称、选题关键词），
比凭印象回想可靠得多——这批词最容易在"补充细节"的时候被顺手带回去。

### 5.2 数据必须带来源标记

任何来自当事人自述的数字，必须在同句或紧邻处标注。常用写法：

- `（均为自述，未经核验）`
- `（现场走访自述）`
- 表格里单独设"依据"列：`现场走访自述` / `访谈案例` / `双方讨论` / `访谈提及`

按可信度排：`双方讨论` > `访谈案例` > `现场走访自述` > `个人推测`。
不要把不同可信度的数据平铺在同一句里不加区分。

### 5.3 推算与概括

只有引用和转述时，句子不要加引号。
要保留原话质感时用间接引语：把原话里的口语成分去掉、时态统一、不加"他说"这类重复主语。
**不要**为了"像纪要"而把转写稿的口头禅也搬进来。

## 6. 议题块的标准写法

一个议题块 = 议题名（L1）+ 方面（L2）+ 事实（L3）。

好的 L3 有这三个特征：

1. **可独立成立**——单句读得懂，不依赖上一句。
   ❌"另外还有一些政策方面的信息没有覆盖到。" → ✅"科技园等实体载体三年未向研究生推送入驻通知，入住条件无从获知。"
2. **带限定**——把原文里的模糊语气（"好像""可能""基本上"）按实际强度保留，
   不要为了利落一律改成确定句。
3. **不夹带评价**——事实和判断分开写。"他很不专业"是评价，不进纪要；
   "由推荐机制决定是否触达"是机制，写进纪要。

## 7. 行动项

每条行动项必须能回答四个问题：**做什么、谁做、什么时候之前、依据哪场讨论**。

- 做什么：用动宾开头（"与…沟通，核实…""就…组织一次专题讨论"）。
- 谁做：用角色（"校方代表"/"社区运营方"/"双方共同"）。
- 什么时候：用相对期限（"两周内""三周内""一个月内"），
  原文给了绝对日期就用绝对日期。
- 依据：能回指到某个议题就回指；实在没有就不写这条，别硬凑。

行动项不是会议里说过的所有待办的搬运。要区分：
"会上讨论过这件事" ≠ "会上有人认领了这件事"。
只写后者，或者在"后续讨论"里明确写成"待明确事项"。

## 8. 纪要末尾的处理口径

"记录与保密说明"这一段固定交代四件事：

1. 整理方式（依据转写记录，统一标点、合并被切分语句、订正可由上下文校验的识别错误，未作实质性增补或删改）。
2. 脱敏范围（哪些内容不予记录）。
3. 数据性质（涉及经营与收入的表述均标注为当事人自述）。
4. 传阅范围与时效（内部材料、限范围内传阅、判断以某时点为准）。

这一段是纪要的免责与溯源入口，缺了它，前面所有"自述""未核验"的标注都悬空。

## 9. 从原话到纪要句：三个例子

**例 1 · 抽事实并给角色**

- 原话：`"我们二期的格子间是不收租金的，工位、柜子、饮水都有，晚上现在也不限了，原来是说十点，后来发现确实有人在熬夜干活，就给放开了。"`
- 纪要：`二期启用后整体迁入，格子间免租，配工位、储物柜与饮水设备；夜间使用初截止 22 时，因确有夜间工作需求而放开，目前实际不限时。`
- 做了什么：去掉口语与重复，把"为什么放开"的原因补进同一句（原文有，只是被拆散了）。

**例 2 · 区分主张与结论**

- 原话：`"我们这边感觉吧，现在真不缺技术，缺的是能推得动的人。"`（社区运营方）
- 纪要：`社区运营方提出：现在最不缺技术，能把项目往前推的人很少。`
- 对照（会议认可的说法）：`会议形成的判断是，能否跑通一个稳定的盈利点是衡量商业闭环的标准。`

**例 3 · 数字加来源**

- 原话：`"两个号，一个六万九粉，另一个才跑了两个月两千粉左右。"`（在读研究生）
- 纪要：`在读学生提供的样本是账号内容代运营：图文笔记由人工智能生成后转成图片，每日更新一条，月收入约 2100 元；两个财经类账号中一个累计约 6.9 万粉，另一个运行两个月余约 2000 粉（均为自述，未经核验）。`
- 做了什么：数字全部保留并加标注；同时补上另一个同样重要但原稿散落在别处的数字（月收入），因为它属于同一条事实链。
